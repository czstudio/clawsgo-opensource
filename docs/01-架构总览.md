# 01 · 架构总览

## 1. 双站点结构

ClawsGO 不是一个单体应用，而是**三个独立部署**，通过域名和区域配置协作：

```
                      ┌──────────────────────────────┐
   clawsgo.cn   ───▶  │  营销站  Next.js (App Router) │  静态预渲染 ×5
                      │  Turbopack 构建               │
                      └──────────────┬───────────────┘
                                     │ CTA → app.clawsgo.cn
                                     ▼
                      ┌──────────────────────────────┐
   app.clawsgo.cn ──▶ │  应用端  React 19 + Vite      │  SPA，登录墙后
                      │  nginx 托管                   │  601 chunks
                      └──────────────┬───────────────┘
                                     │ POST /api/{command}
                                     ▼
                      ┌──────────────────────────────┐
   api.clawsgo.cn ──▶ │  API 网关（源码不可得）        │  204 个命令
                      └──────────────────────────────┘
```

### 判断依据

| 证据 | 说明 |
|---|---|
| `X-Powered-By: Next.js`、`X-Nextjs-Cache: HIT`、`X-Nextjs-Prerender: 1` | 营销站是 Next.js 预渲染 |
| `Vary: rsc, next-router-state-tree, ...` | 用的是 App Router（RSC） |
| `Server: nginx/1.31.5` + `Last-Modified` 而非 `Etag: "ly8blg..."` | 应用端是 nginx 托管静态产物，不是 Next.js |
| 应用端 `index.html` 里全是 `type="module" crossorigin` + `/assets/` 哈希 | Vite/Rolldown 构建 |
| 入口含 `rolldown-runtime-hePW80VL.js` | 用的是 **Rolldown**（Vite 的 Rust 打包器），非 esbuild 系 |

## 2. 区域化双品牌（关键设计）

从 `region-DPAjEUXn.js` 还原出的构建期区域配置——这是整个产品最核心的架构决策：

```js
const REGIONS = {
  cn: {
    id: 'cn',
    gateways: ['wechat'],  defaultGateway: 'wechat',
    authMethods: ['phone'],
    invoicing: true,
    siteUrl: 'https://clawsgo.cn',
    appUrl:  'https://app.clawsgo.cn',
  },
  global: {
    id: 'global',
    gateways: ['stripe'],  defaultGateway: 'stripe',
    authMethods: ['google'],
    invoicing: false,
    siteUrl: 'https://clawsgo.ai',
    appUrl:  'https://app.clawsgo.ai',
  },
};

const SELECTED = 'cn';   // 构建期常量
if (!isValidRegion(SELECTED))
  throw Error(`VITE_REGION 必须是 cn|global 之一，当前值 "${SELECTED}"（apps/app/.env）`);
```

**解读：**

- 同一份代码库构建出两个品牌，用 `VITE_REGION` 环境变量切换。构建期就硬编码进产物（`SELECTED` 是字面量 `"cn"`），运行时不可切。
- 区域决定三件事：**支付网关**（微信 vs Stripe）、**登录方式**（手机号 vs Google）、**是否开具发票**（中国需要，海外不需要）。
- 报错信息里的 `apps/app/.env` 泄露了 monorepo 布局：`apps/app`（应用）、`apps/site`（营销站），典型 pnpm workspace 结构。

## 3. 前端技术栈（从 bundle 实证）

| 层 | 选型 | 证据 |
|---|---|---|
| 框架 | React 19 | `react-CwJFpaho.js`、`react-dom-DX3XddaT.js` |
| 构建 | Vite + Rolldown | `rolldown-runtime-hePW80VL.js`，chunk 命名 `Name-Hash.js` |
| 路由 | **TanStack Router**（文件式） | `route-Bzc6xn5x.js` 含 `createFileRoute` 语义、`_app` / `_shell` 嵌套布局 |
| 数据 | **TanStack Query** | `QueryClientProvider`，`staleTime: 30000`、`refetchOnWindowFocus: false` |
| 状态 | Zustand | `useStore-Ba_dQPqf.js` |
| UI 基座 | **Base UI**（MUI Base，非 Radix） | `FloatingPortal` / `usePositioner` / `DirectionContext` / `useBaseUiId` |
| 样式 | Tailwind CSS v4 | CSS 里 `--tw-*` 变量、`@keyframes enter/exit` 为 tailwindcss-animate 特征 |
| 动画 | **Framer Motion**（`motion/react`） | `variants` / `layoutId` / `AnimatePresence` / `transition:{type:"spring"}` |
| i18n | **Paraglide JS** | 1012 个键；每个键一个 chunk（`admin_col_balance`、`billing_invoice_reversed`…） |
| 图标/头像 | DiceBear | `www.dicebear.com` |
| 验证码 | 阿里云 AliyunCaptcha | `window.AliyunCaptchaConfig = { region:'cn', prefix:'w2cj5a' }` |

### 注意：不是 Radix / shadcn

`FloatingPortal`、`usePositioner`、`DirectionContext` 全部来自 **Base UI**（`base-ui.com`）。同时存在 `cn(...)` 风格的 className 合并，说明是 shadcn 风格的组织方式 + Base UI 底座。

## 4. 应用端目录推断

从 chunk 命名、路由结构和 i18n 键，可反推出源工程大致长这样：

```
apps/
├─ app/                       # app.clawsgo.cn
│  ├─ .env                    # VITE_REGION=cn
│  └─ src/
│     ├─ routes/
│     │  ├─ __root.tsx
│     │  ├─ _app.tsx               # 登录后外壳（侧栏 + 顶栏）
│     │  ├─ _app/
│     │  │  ├─ chat/
│     │  │  │  ├─ index.tsx
│     │  │  │  └─ $conversationId.tsx
│     │  │  ├─ home/  skills/  hosts/  teams/
│     │  │  ├─ invites/  redeem/  invoices/  tickets/
│     │  │  └─ admin/
│     │  │     ├─ index.tsx  users.tsx  hosts.tsx  teams.tsx
│     │  │     ├─ payments.tsx  invoices.tsx  growth.tsx
│     │  │     ├─ invites.tsx  promoters.tsx  redeem.tsx
│     │  │     ├─ risk.tsx  audit.tsx  announcements.tsx
│     │  │     └─ tickets/$ticketId.tsx
│     │  ├─ _shell/                # 无侧栏的独立壳
│     │  ├─ (auth)/login.tsx        # 登录（OTP / 密码 tab）
│     │  ├─ desktop-auth.tsx        # 桌面端一次性 token 授权
│     │  └─ share/$conversationId.tsx
│     ├─ lib/api.ts                # ← 就是 api-pyi_9PXn.js
│     ├─ locales/                  # Paraglide 消息
│     └─ components/
└─ site/                      # clawsgo.cn（Next.js）
```

其中 `_app` / `_shell` 在产物里是显式路由段（`/_app/admin/users`、`/_shell` 都出现在路径字面量中），这是 TanStack Router 的**路径less 布局路由**写法。

## 6. 数据流

```
用户输入
   │
   ├─ POST /api/sendMessage ────────▶ 创建一轮对话
   │
   ├─ SSE  text/event-stream ───────▶ useConversationStream
   │     (useConversationStream-C0Qxn0G5.js)   流式返回 token / tool 事件
   │
   ├─ POST /api/getMessages ────────▶ 拉取已落库的消息
   │
   └─ 产物链路
        ├─ getConversationFiles       列文件
        ├─ getConversationFileIndex   文件索引（供 agent 检索）
        ├─ getConversationGitStatus   工作区 git 状态
        ├─ getConversationGitDiff     改动 diff（"可溯源的过程" 功能）
        ├─ compileLatex               LaTeX 编译
        └─ downloadConversationFile   导出（返回 Blob）
```

「可溯源」是这个产品的核心卖点，对应实现就是 **git status / git diff + 文件索引 + 终端会话** 三件套——每个 agent 动作都落在真实工作区里，所以能重放。
