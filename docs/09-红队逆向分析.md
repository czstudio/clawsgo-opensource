## 二、终端/云主机实现（真实）

### 2.1 架构

**不是 Docker/WebContainer，是真 SSH + 远程 Shell**：

```
前端 xterm.js ←→ WebSocket ←→ 后端 SSH 代理 ←→ 真实云主机
```

### 2.2 WebSocket 协议

**连接流程**（`_shell-DLMlr5Wy.js` offset 167739）：
1. `attachProjectTerminal` / `attachTerminal` → 获取 ticket
2. WebSocket 连接（URL 含 ticket）
3. 消息格式：
   - `{t: "data", bytes: ...}` - 终端输出
   - `{t: "exit"}` - 进程退出
   - `{t: "reason", ...}` - 错误原因

**连接状态机**：
- `connected` → 正常
- `link_lost` → 连接断开
- `failed` → 连接失败
- `session_gone` → 会话不存在

**错误码**：
- `NOT_FOUND` → 终端不存在
- `HOST_OFFLINE` → 云主机离线

### 2.3 前端行为

> "正在读取文件清单，唤醒云主机可能需要等待片刻"
> "Reading files, waking the cloud host may take a moment"

云主机是**按需唤醒**的（sleep/wake 机制）。

## 十二、大模型后训练模块分析（关键发现）

### 12.1 核心结论

**生产 bundle 和后端 API 中不存在"模型后训练管理界面"或"在线训练模块"。**

证据：
1. **266 条后端命令中，0 条与 train/fine-tune/RLHF/DPO/PPO 相关**
2. **1098 个前端 chunk 中，没有任何模型训练/标注/评估的 UI 组件**
3. **Admin 后台（`admin-3P0VhtiT.js`，12KB）中没有可读的模型管理字符串**

### 12.2 "后训练"的真实含义

ClawsGO 的"后训练"是**离线流程**，不是线上功能：

> "Built on top-tier open-source base models, post-trained and fine-tuned for ClawsGO Science Harness, with high-quality chain-of-thought data"
> 
> — `app/assets/ChatStatusBar-CMXxaPi9.js`（模型描述文案）

**实现方式（推测）**：
1. 使用 `adminGetChatConversations`、`adminGetConversationCosts` 等命令**收集对话数据**
2. 离线进行 SFT/DPO/RLHF 训练
3. 训练好的模型通过 `clawsgo-1.5-*` 命名发布
4. 前端通过模型选择器切换不同版本的模型

### 12.3 线上 vs 本地复刻的差异

| 维度 | 线上真实 | 本地复刻 | 证据 |
|------|---------|---------|------|
| 底层模型 | DeepSeek + OpenAI + Anthropic + 智谱 + Google | 无 | `ChatStatusBar-CMXxaPi9.js` |
| 模型后训练 | 离线 SFT/DPO/RLHF | 无 | 无相关命令/chunk |
| 对话数据收集 | `adminGetChatConversations` 等 | 有相同数据结构 | `server/api/admin.mjs` |
| 模型推理 | 真实 LLM 推理 | 规则引擎模拟 | `server/api/chat.mjs` |
| Chain-of-thought 数据 | 高质量 CoT 数据训练 | 无 | `ChatStatusBar-CMXxaPi9.js` |
| Science Harness | 专门的科研任务优化 | 无 | `ChatStatusBar-CMXxaPi9.js` |

### 12.4 拿不准的部分（诚实声明）

以下信息**无法从生产 bundle 中确认**：

## 十三、LLM 模型调用机制（完整实现）

### 13.1 配置方式

**本地复刻**（`server/lib/agent.mjs:25-29`）：
```javascript
const LLM = {
  baseUrl: process.env.CLAWSGO_LLM_BASE_URL || '',
  apiKey: process.env.CLAWSGO_LLM_API_KEY || '',
  model: process.env.CLAWSGO_LLM_MODEL || '',
};
```

**启动方式**：
```bash
CLAWSGO_LLM_BASE_URL=https://api.openai.com/v1 \
CLAWSGO_LLM_API_KEY=sk-xxx \
CLAWSGO_LLM_MODEL=gpt-4o \
node server/serve.mjs
```

### 13.2 请求格式（OpenAI 兼容）

**端点**：`POST {baseUrl}/chat/completions`

**Headers**：
```
Content-Type: application/json
Authorization: Bearer {apiKey}
```

**Body**（`server/lib/agent.mjs:541-554`）：
```json
{
  "model": "clawsgo-1.5-lithium",
  "stream": true,
  "messages": [
    {
      "role": "system",
      "content": "你是 ClawsGO Science 的长时程科研智能体..."
    },
    {
      "role": "user", 
      "content": "用户问题..."
    }
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "Read",
        "description": "读取工作区中的文本文件",
        "parameters": {
          "type": "object",
          "properties": {
            "file_path": { "type": "string" }
          },
          "required": ["file_path"]
        }
      }
    }
  ],
  "tool_choice": "auto"
}
```

### 13.3 系统提示词（完整）

```
你是 ClawsGO Science 的长时程科研智能体。工作区是一台隔离沙箱，
你只能用给定工具操作它。先用工具核对事实，再给出结构化结论：
结论 → 证据 → 复现步骤。中文回答，Markdown 排版。
```

### 13.4 工具 Schema（7 个工具）

| 工具名 | 描述 | 参数 |
|--------|------|------|
| `Read` | 读取工作区文本文件 | `file_path` |
| `Write` | 写入文件（覆盖） | `file_path`, `content` |
| `Glob` | 按 glob 模式列文件 | `pattern`, `path` |
| `Grep` | 在工作区中正则检索 | `pattern`, `path` |
| `Bash` | 执行 shell 命令（需授权） | `command`, `description` |
| `WebSearch` | 联网检索 | `query` |
| `WebFetch` | 抓取网页正文 | `url` |

### 13.5 返回格式（SSE 流）

```
data: {"choices":[{"delta":{"reasoning_content":"先分析..."}}]}
data: {"choices":[{"delta":{"content":"根据分析..."}}]}
data: {"choices":[{"delta":{"tool_calls":[{"function":{"name":"Bash","arguments":"{\"command\":\"ls\"}"}}]}}]}
data: [DONE]
```

**Delta 字段解析**（`server/lib/agent.mjs:601-620`）：
- `delta.reasoning_content` → reasoning part（推理过程）
- `delta.content` → text part（最终回答）
- `delta.tool_calls[].function.name` → 工具名
- `delta.tool_calls[].function.arguments` → 工具参数（JSON 字符串，需累积）

### 13.6 前端发送的参数（从 bundle 提取）

**`chat-D1Hp5-8h.js:84998`** 构造的请求参数：
```javascript
{
  modelId:         d.modelId,        // "clawsgo-1.5-lithium" 等
  subagentModelId: d.subagentModelId, // 子智能体专用模型
  effort:          d.effort,          // 努力程度
  mode:            d.mode,            // 模式
  context:         d.context          // 上下文长度
}
```

### 13.7 工具调用循环（真实执行流程）

```
1. 发送 messages + tools 给 LLM
2. LLM 返回 reasoning_content（推理过程）
3. LLM 决定调用工具 → 返回 tool_calls
4. 前端显示权限请求（Bash 需用户批准）
5. 后端真实执行工具（读盘/写盘/执行命令）
6. 工具结果作为 tool 消息追加到 messages
7. 再次发送给 LLM（最多 8 轮）
8. LLM 返回最终 content（结论）
```
